## How to re-theme

The whole system is regenerated from `brand.json` and optional
`brand.json.seed` overrides. Persist authored overrides there, then run
`od brand finalize <brand-id>` — every downstream token, component and artifact
follows. Do not edit `system/seed.json` directly; finalize replaces it.

- **Change the brand color:** edit the accent role or `seed.colorPrimary` in `brand.json`.
  The 10-step palette, all interaction states, the primary background/border and
  every component that references `var(--brand-color-primary)` update together.
- **Light → dark:** the dark theme is the same seed run through the `"dark"`
  algorithm — load `variables.dark.css` (or add the `.dark` class).
- **Density:** the `"compact"` algorithm tightens spacing & control heights
  while keeping colors identical.

## Add a new artifact type

`renderArtifact(kind, brand, tokens)` already accepts every `AssetKind`
(`landing | deck | poster | email | newsletter | form`). Add the kind to the
build's artifact list to ship it in the bundle; kinds without a bespoke layout
fall back to a sensible card+button page.

## Lattix reconciliation layer

| Property | Value |

| Brand | Lattix |
| Legal entity | Lattix Technologies Corp. |

**Model:** blended — Lattix brand layer, Kumo-style component layer, ISA-101 operational status layer (see DESIGN.md). Primary actions use the interaction colour (light #1f5fd6, dark #2f62d4); status colour appears only for abnormal states; simulated, proposal and shadow-mode states are violet.

The generator above derives dark mode from one seed and cannot express a separate dark interaction colour or the status grammar. After every `od brand finalize`, run `node canonical/reconcile.mjs`; it compiles `canonical/lattix-tokens.json` into `lattix-theme.css`, appends a canonical override block to `variables.css` / `variables.dark.css`, writes `theme.json` + `theme.dark.json`, renders `kit.html` / `kit.dark.html` from `canonical/src/kit.template.html`, and patches the remaining generated HTML. Then run `node canonical/validate.mjs`.

`artifacts/` (landing, deck, poster, email, newsletter, form) is generator collateral, out of scope for the operational component library.
